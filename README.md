# ЛУК.AI — AI-стилист

Лендинг + рабочая демка подбора образов из личного гардероба, плюс backend
и Telegram-бот на общей логике подбора.

## Структура

```
luk-ai/
├── index.html          # разметка лендинга и демки
├── css/style.css        # все стили, дизайн-система через CSS-переменные в :root
├── js/app.js            # логика демки в браузере
├── shared/
│   └── outfit-logic.js  # общий алгоритм подбора — используется и сайтом, и ботом
├── server/               # Express + SQLite backend
│   ├── server.js
│   ├── db.js
│   └── package.json
└── bot/                   # Telegram-бот
    ├── bot.js
    └── package.json
```

## Дизайн-система (css/style.css, :root)

- `--black` (#141009) / `--black-soft` / `--panel` (#2e2910, Drab Dark Brown) — фоны
- `--accent` (#eb7d00, Tangerine) / `--accent-dim` — основной акцентный цвет (CTA, кнопки, цифры)
- `--accent-2` (#2c5745, Brunswick Green) — вторичный акцент
- `--white` (#ebe3a7, Vanilla) / `--grey` — текст
- `--line` — границы/разделители

## Что работает по-настоящему

- **Гардероб сохраняется между визитами** — `localStorage` (`js/app.js`,
  ключ `luk-ai-wardrobe-v1`). Картинки (blob-URL) не переживают перезагрузку
  сами по себе, но тип/цвет/название вещи — сохраняются.
- **Умный подбор образа по цвету** — `shared/outfit-logic.js`: цвета
  переводятся в HSL, вещи оцениваются попарно (нейтральные — сочетаются со
  всем, близкие или дополняющие оттенки — хорошо, «грязная середина» на
  цветовом круге — плохо), из вещей перебираются все комбинации
  верх+низ(+верхняя одежда при холоде)+обувь и берётся одна из трёх лучших
  по сумме сочетаемости — так подбор не залипает на одном и том же луке.
- **Карточка «Сегодняшний лук» в hero-блоке запрашивает погоду сама** —
  `initHeroWeather()` (`js/app.js`) при заходе на сайт сама вызывает
  `navigator.geolocation.getCurrentPosition` (браузер покажет свой стандартный
  запрос доступа к местоположению у любого посетителя, не только у
  вернувшегося). Температура в hero всегда настоящая, как только доступ
  получен — статичный пример «+18°» подставлен только как заглушка на
  самый первый рендер страницы, до ответа геолокации/погоды. Если в
  гардеробе уже есть 2+ вещи — заодно пересобирается и сам лук (цвета,
  вещи, % сочетаемости), иначе обновляется только цифра температуры, а
  иллюстративные свотчи остаются как пример.
- **Лук сам меняется при заметном скачке погоды** — пока страница открыта,
  раз в 10 минут (`HERO_POLL_INTERVAL_MS`) тихо перепроверяется температура,
  и если она сдвинулась на 3°C и больше (`HERO_TEMP_CHANGE_THRESHOLD`) с
  прошлого пересчёта — hero-лук и кнопка погоды в демке пересобираются под
  новую температуру. Небольшие колебания (±1-2°) лук не трогают.
- **Бегущая строка бесшовная на любой ширине экрана** — `setupMarquee()`
  (`js/app.js`) измеряет ширину контейнера и повторяет фразы, пока половина
  дорожки не станет шире экрана, потом подгоняет длительность анимации под
  постоянную скорость (px/сек) — раньше на широких мониторах между повторами
  было видно пустое место, потому что текст дублировался фиксированное
  число раз.
- **«Чего не хватает в гардеробе»** — под гардеробом в демке появляется
  список типов вещей, которых нет вообще (например, обуви), с реальными
  рабочими ссылками на поиск по Wildberries и Ozon (`renderShoppingSuggest()`
  в `js/app.js`). Без партнёрского API маркетплейса это честный работающий
  вариант — открывает настоящую выдачу товаров по клику, а не «нарисованные»
  карточки. Цветовой подбор из своего гардероба при этом никуда не делся —
  это дополнение, а не замена. Пользователь может выбрать и запомнить, где
  искать (Wildberries / Ozon / оба) — выбор сохраняется в localStorage
  (`luk-ai-marketplace-pref-v1`) и применяется при следующих визитах.
- **Тип вещи при загрузке фото теперь выбирает пользователь, а не угадывает
  код** — раньше тип назначался вслепую по счётчику добавленных вещей
  (`wardrobe.length % 4`), из-за чего вещи попадали в случайные категории.
  Теперь после загрузки фото появляется явный выбор (верх/низ/верхняя
  одежда/обувь), и только после него вещь добавляется в гардероб.
- **Исправлены два реальных бага в зоне загрузки фото:**
  1. `.upload-zone` — это `<label>`, который по умолчанию `display:inline`;
     из-за этого рамка и фон рендерились фрагментированно вокруг строк
     текста, а не как единый прямоугольник — отсюда странная кривая линия
     слева от заголовка «1. Твой гардероб». Исправлено добавлением
     `display:block`.
  2. Клик по зоне загрузки не открывал выбор файла в части браузеров: код
     дёргал `e.preventDefault()`, а потом вручную `fileInput.click()` —
     но `<label>`, оборачивающий `<input type="file">`, и так нативно
     открывает выбор файла по клику безо всякого JS; ручной обработчик
     был не нужен и местами ломал это поведение. Просто убрали его.
- **Совет вместо простого списка вещей** — после подбора образа
  `OutfitLogic.suggestSwap()` проверяет, есть ли в гардеробе замена одной
  вещи, которая заметно (на 10%+) улучшит сочетаемость; если да — показывает
  конкретный совет («замени Х на Y», с процентами до/после), если нет —
  явно подтверждает, что менять ничего не нужно.
- **Реальная погода** — кнопка «Определить погоду автоматически» спрашивает
  геолокацию браузера и дёргает бесплатный [Open-Meteo](https://open-meteo.com/)
  (без API-ключа), температура переводится в холодно/прохладно/тепло.
  Ручные кнопки остаются как запасной вариант.
- **Цвет вещи по фото** — при загрузке своего фото картинка уменьшается на
  canvas и усредняется по пикселям, чтобы вытащить доминантный HEX-цвет.
  Это работает полностью в браузере, без внешних сервисов.
- **Backend (`server/`)** — Express + встроенный в Node `node:sqlite`
  (без нативных зависимостей). REST API: гардероб пользователя (`/api/wardrobe`),
  подбор образа на сервере (`/api/outfit`), статус и «оформление» подписки
  (`/api/subscription*`).
- **Telegram-бот (`bot/`)** — на `node-telegram-bot-api` + `jimp` (чистый JS,
  без нативных биндингов для обработки фото), переиспользует
  `shared/outfit-logic.js` и ту же базу, что и backend. Команды: `/add`,
  `/wardrobe`, `/look`, `/remove <id>`.

## Что подделано (мок), потому что нужны внешние ключи/аккаунты

- **Оплата подписки** — в `server/server.js` эндпоинт
  `/api/subscription/checkout` сразу помечает пользователя подписанным,
  без реального списания денег. Для настоящей оплаты нужен аккаунт и ключи
  платёжного провайдера (например, ЮKassa/CloudPayments/Stripe) — тогда
  чекаут создаёт платёж в API провайдера, а активация подписки переносится
  в отдельный вебхук-эндпоинт, который провайдер дёргает сам после оплаты.
- **Telegram-бот не запущен онлайн** — код рабочий и протестирован на
  синтаксис/логику, но для запуска нужен токен от [@BotFather](https://t.me/BotFather).
- **Полное распознавание типа вещи по фото** (не только цвета) потребовало
  бы vision-модель/API — сейчас тип по-прежнему выбирается вручную при
  добавлении, а цвет определяется автоматически.

## Запуск

### Сайт
Статика — просто открой `index.html` в браузере или подними любой
статик-сервер: `python3 -m http.server` из папки `luk-ai/`.

### Backend
```
cd server
npm install
npm start        # node --experimental-sqlite server.js, слушает :3001
```

### Telegram-бот
```
cd bot
npm install
TELEGRAM_BOT_TOKEN=xxxxx npm start
```
Токен получить у [@BotFather](https://t.me/BotFather) командой `/newbot`.
